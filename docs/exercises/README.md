# 智能座舱配套练习题

[返回教程首页](../README.md) · [开发指南](../DEVELOPMENT.md)

本题库与 **14 篇教程逐章对应**，另有一套开发指南源码综合题，共 **15 套、120 道题**。它不是让你立即改参考项目，而是帮助你在自己的学习目录里，从解释概念逐步做到实现、复现故障和提供验证证据。

## 1. 每一套怎样做

每套 8 题，共 100 分，统一题号便于交作业和复盘：

| 题号后缀 | 类型 | 分值 | 应交什么 |
| --- | --- | --- | --- |
| 01～03 | 基础概念 | 每题 5 分 | 自己的话、判断理由或简图 |
| 04 | 手算 / 代码与事件推演 | 15 分 | 中间步骤、数值或状态序列 |
| 05～06 | 动手实践 | 每题 20 分 | 学习工程、测试或指定的静态审查产物 |
| 07 | 故障分析 | 15 分 | 最小复现、原因、修复方向与回归点 |
| 08 | 综合任务 | 15 分 | 跨知识点的设计、验证记录或验收报告 |

先独立完成，再展开每份底部的“参考答案与评分提示”。概念题有关键答案；设计和编码题给出可核对的检查点，不要求代码逐字相同，也不直接交出完整成品。

建议按 **读教程 → 做 01～04 → 写 05～06 → 分析 07 → 完成 08 → 对答案 → 重做错题** 的顺序。13、14 和开发指南综合题可以分多次完成，不需要一口气做完。

## 3. 学习目录与提交约定

沿用教程变量；新终端需要重新设置，参考仓库路径不同则修改第一行：

```bash
PROJECT=/home/air/qt/Smart_Cockpit_based_on_tspi
WORK="$HOME/smart-cockpit-lab"
ls "$PROJECT/docs" "$PROJECT/src"
```

推荐自己的作业目录如下。这是目录示意，不是需要全部一次创建的项目骨架：

```text
$WORK/exercises/
  01/answer.md
  02/answer.md + 手写的小工程
  ...
  13/answer.md + 对自己的完整工程的说明
  14/answer.md + 缺陷修复记录
  development/answer.md + 源码追踪记录
```

- 每题以完整题号记录：例如 `04-04`；开发指南使用 `DEV-01`。
- 编码题写自己的文件，或复制教程实验到学习目录后修改；不要覆盖参考仓库及已有作业。
- 源码和构建产物分开。13 可继续使用 `$WORK/cockpit` 与 `$WORK/build-cockpit`，题目报告放在 `exercises/13`。
- 每项实验至少记录：输入、预期、实际、结论、环境。截图可以辅助证明 UI，但不替代字节、信号或状态断言。
- 代码片段若标注“阅读片段”，不应当成完整文件直接构建。命令中的变量必须先定义。
- 不要求提交 Git commit、上传文件、安装系统依赖或修改真实设备；自己保留可复现产物即可。

## 4. 没有硬件也能完成什么

基础 C++、Qt 服务注入、日志与大部分测试只需开发机；摄像头可使用 GStreamer 测试源。音频、真实显示、SocketCAN、ARM SDK 和板端设备不足时，按题目做静态检查、事件推演或测试设计，并明确标注缺失条件。

**纸面分析不是实测，fakesink 不是有声播放，offscreen 不是完整 GL 验收，主机测试不是板测。** 未运行的结果写“预期 / 待验证”，不要为了得分编造“通过”。涉及设备的题目允许提交明确的替代作业，但验收表仍应保留“未实测”。

所有 CAN 控制实验只允许自己的隔离教学环境；不向在用车辆发帧。部署题默认做纸面审查，不执行远端复制、服务启停或权限修改。需要真正上板时，另外确认设备、权限和回退方案。

## 5. 自评与复盘

- **90～100 分**：概念、实现与证据基本连贯；再检查自己有没有夸大验证范围。
- **70～89 分**：可以继续下一章，同时补齐失分项。
- **不足 70 分**：先回到对应教程做最小实验，再重新回答关键题。

分数只反映练习完成度，不是车辆功能安全、产品可用性或全平台认证。更重要的是你能否解释“为什么这样做”，以及发现失败时能否用证据定位问题。

建议错题记录三列：**我原来怎样理解 → 哪条证据推翻了它 → 下次怎样验证**。

从 [01 环境练习](01-environment.md) 开始；已有基础也可以直接选择薄弱章节。
