- 前置：完整阅读对应教程；了解 C++17 线程、互斥锁、条件变量和 Qt 信号槽。
- 建议时间：基础与推演 45 分钟，实践 90 分钟，排障与验收 45 分钟。
- `$WORK` 约定为仓库外、普通用户拥有的学习根目录，例如 `$HOME/smart-cockpit-lab`。
- 本章目录为 `$WORK/exercises/10`，下设 `source-copy/`、`cases/`、`logs/`、`evidence/`；用编辑器或文件管理器准备。
- 原项目仅作只读参考；代码、构建、日志和故障注入只能发生在学习副本中，不修改原仓库。
- 不需要 SDK、板子、真实 CAN 或摄像头；缺少宿主依赖时提交测试设计与手算结果，注明“未运行”，知识题照常评分。
- 禁止通过提权、改权限、服务控制或向车辆发帧完成练习；不要用异常杀进程证明日志排空。
- 共 8 题，分值依次为 5、5、5、15、20、20、15、15，总分 100 分。

阅读入口：[日志核心](../../src/logging/AsyncLoggerCore.cpp)、[Qt 日志适配](../../src/logging/AsyncLogger.cpp)、[健康监控](../../src/core/HealthMonitor.cpp)。

### 10-01 找到生产者、消费者与锁的边界（5分）

**输入/约束：** 阅读 `log()` 和 `writerLoop()`，假设两个生产者、一个消费者，文件已经成功打开。
只画当前实现，不将其改写成 QThread/QMutex，不引入额外写线程。

**任务：** 画出“检查等级→入队→唤醒→等待谓词→取 batch→写入”的流程。
在图中标注锁的持有区间、共享队列与局部 batch 的归属，并解释磁盘变慢时哪些操作仍可能阻塞生产者。

**提交物：** 一张流程图或缩进时序表，附两句成本说明。

**验收/评分点：** 角色及等待谓词正确 2 分；`batch.swap(m_queue)` 与锁外格式化/写文件正确 2 分；指出锁等待、字符串复制或内存分配成本 1 分。

### 10-02 给日志承诺划边界（5分）

**输入/约束：** 以下五条宣传语均针对当前实现，不是假设改进版。

1. “队列有容量上限，磁盘再慢也不会持续占用内存。”
2. “每条记录写入前检查 10 MB，文件绝不会超限。”
3. “每次轮转新增一个备份，因此能永久保留历史。”
4. “每批 flush，所以掉电前的记录一定落在物理介质上。”
5. “先调用 stop，再让业务线程退出，一定能够完整排空。”

**提交物：** 逐条判定并改成可被源码支持的一句话；轮转阈值同时写单位和精确字节数。

**验收/评分点：** 每条纠错 1 分；必须涉及无界队列、批后轮转、一份 `.1`、`flush != fsync`、先停生产者再 stop。

### 10-03 写出健康判定式（5分）

**输入/约束：** 服务指针可能为空；CAN age 定义为 `now - lastFrameTimeMs()`，相机 age 取 `lastFrameAgeMs()`。
年龄单位均为 ms；媒体可能初始化成功但尚未播放。

**任务：** 写出三个 alive 布尔式及 Normal/Degraded/Emergency 的选择顺序。
说明“连接成功”和“正在运行”为何都不能单独证明健康，年龄等于阈值时如何处理。

**提交物：** 三个判定式、一张三行优先级表、一个媒体空闲反例。

**验收/评分点：** CAN 指针、connected、`age < 3000` 完整 2 分；相机指针、running、`age < 2500` 及媒体 healthy 完整 2 分；Emergency 优先且空闲不等于不健康 1 分。

### 10-04 手算轮询、信号与批后轮转（15分）

**输入/约束：** 初始状态为 Normal；下表是按序人工触发的七次 poll 快照，不要求相邻快照相隔 2000 ms。
三个服务指针均非空；每行的 age 是本次采样输入，不从上一行外推。

| poll | CAN connected / age | 相机 running / age | 媒体 healthy |
| --- | --- | --- | --- |
| P0（start 的立即 poll） | true / 100 | true / 100 | true |
| P1 | true / 2999 | true / 2499 | true |
| P2 | true / 2999 | true / 2500 | true |
| P3 | true / 3000 | true / 2600 | false |
| P4 | false / 10 | true / 10 | true |
| P5 | true / 10 | true / 10 | false |
| P6 | true / 10 | true / 10 | true |

另有当前日志文件 10,485,700 字节，旧 `.1` 已存在；取出的 batch 含两条各占 100 字节的完整格式化记录。
假设无其他写入，文件操作全部成功；计算本批结束时当前文件与备份的状态。

**提交物：** 七行状态和两个信号的发送标记、总次数；轮转前后字节数；默认轮询周期为何不是硬截止时间。

**验收/评分点：** 七个状态 7 分；`stateChanged`/`diagnosticsChanged` 次数 3 分；轮转算术与备份去向 3 分；定时器与事件循环延迟解释 2 分。

### 10-05 实践：四行日志，而不是固定的四行顺序（20分）

**输入/约束：** 在学习副本中使用纯 C++17 日志核心，阈值设为 `Warn`。
线程 A、B 各顺序调用一次 INFO、WARN、ERROR；消息包含本轮唯一标记及线程名，记录内容足够小，不触发轮转。
每轮使用新的 `$WORK/exercises/10/logs/run-标记/`，不向系统日志目录写入。

**任务：** 编写最小驱动与结果校验器；启动日志后启动两线程，分别 join 后再 stop，最后读取文件校验。
比较本轮消息集合及数量，而不是写死线程间顺序；同时检查每个线程自身 WARN 在 ERROR 之前。
若只能纸面完成，提交逐步驱动伪代码、六次调用和四条应保留消息的精确集合。

**提交物：** 学习副本路径、驱动/断言关键片段、实际日志与退出结果，或注明未运行的等价测试记录表。
记录编译器/依赖情况；程序返回 0、`currentPath()` 有值都不能单独作为启动成功证据。

**验收/评分点：** 六次调用与阈值设置 6 分；四行且 INFO 为零、无重复/遗漏、不过度约束跨线程顺序 8 分；join→stop→读文件 4 分；证据与运行状态诚实标注 2 分。

### 10-06 实践：可复现的健康边界测试（20分）

**输入/约束：** 只在 `$WORK/exercises/10/source-copy/` 建立独立判定器或带测试时钟的监控学习副本。
不要直接修改仓库监控接口；输入为指针存在性、连接/运行标志、采样年龄和媒体 healthy。

**任务：** 将 10-04 的七行转成数据驱动断言，再补以下场景：CAN 指针空、相机指针空、媒体指针空、相机未运行但 age=0。
补测 `CAN connected=true, age=3000` 与 `camera running=true, age=2500`，保证比较符写错会失败。
在带状态的夹具中断言状态变化才通知、每次采样都有诊断；如记录诊断日志，必须由夹具显式连接或调用日志器。
加一个时序案例：模拟器停产但 health 继续 poll，最后一帧后跨过 3000 ms 才被后续 poll 判为 CAN LOST。

**提交物：** 用例表、断言关键片段、测试结果或完整纸面执行轨迹，注明测的是判定副本还是实际 Qt 监控副本。

**验收/评分点：** 三种服务条件和优先级 6 分；阈值与缺失服务用例 6 分；两类通知规则 4 分；诊断并非自动日志 2 分；范围、依赖和未运行项清楚 2 分。

### 10-07 排障：不要用改权限和强退掩盖问题（15分）

**输入/约束：** 以下为虚构故障样本，仅供阅读，不要执行或在系统上复现。

| 样本 | 观察 |
| --- | --- |
| A | 重启日志器后 `currentPath()` 仍有旧路径，终端看不到 qInfo；stderr 提示打不开文件。 |
| B | 日志高峰内存持续增长；退出时业务回调仍在 log，stop 长时间不返回。 |
| C | `--sim` 仪表持续更新、`frames:0`；启动先红，之后 CAN:OK、CAM:FAIL，媒体健康。 |

**任务：** 每例写“两个待核对证据→原因边界→学习副本中的下一步”，不得要求 sudo、chmod、杀进程或创建 vcan。
A 需区分请求目录、当前工作目录下的 fallback 和旧路径；C 需区分接收计数、帧新鲜度与状态优先级。

**提交物：** 三张诊断卡；明确哪些是已有证据，哪些是假设，不把单一现象当唯一根因。

**验收/评分点：** 每例 5 分：取证 2 分、机制解释 2 分、安全下一步 1 分。

### 10-08 综合验收：把状态与日志放进同一条证据链（15分）

**输入/约束：** 使用前两题学习副本或纸面夹具，不接设备；准备正常、相机过期、CAN 过期且媒体失败、恢复四个阶段。
另安排正常退出：停 health、模拟器及其他生产者，覆盖析构/后台回调，再 stop 日志器。

**任务：** 建立验收表：每阶段列输入、期望状态、通知次数、对应日志标记、实际结果/未运行原因。
复用四行过滤实验的计数证据；说明状态恢复必须依赖输入恢复，不能假定 HealthMonitor 自动重连。
列出未证明事项：轮转失败恢复、无限高负载、掉电持久化、并发生命周期、墙时钟跳变及实机功能。

**提交物：** 一页验收矩阵、学习副本相对路径索引、正常退出时序；实际观察与预期分别列栏。

**验收/评分点：** 四阶段及恢复条件 5 分；状态/通知/日志可对应 4 分；限制与未测事项 4 分；退出和证据索引 2 分。
不得把日志 `flush` 或一次桌面运行写成线程安全、硬实时或功能安全认证。

<details><summary>参考答案与评分提示（先独立完成）</summary>

**10-01**
- 生产者持锁检查 running/等级并入队、notify；消费者等待 `!queue.empty() || stopRequested`。
- 消费者仅在“队列空且要求停止”时退出；持锁 swap 到局部 batch，然后释放锁。
- 格式化、文件写入、flush、轮转均在队列锁外；异步不等于无锁等待或无分配成本。
- 画成“消费者持锁写完整批文件”或多个文件消费者，不得对应边界分。

**10-02**
- 五句均不成立：队列无界；写得慢可能积压并消耗内存，没有背压/丢弃策略。
- 阈值为 `10 * 1024 * 1024 = 10,485,760` 字节；整批写完 flush 后检查，达到或超过即尝试轮转。
- 删除旧 `.1`，将当前文件改名为 `.1`，重开当前路径；只保留一份备份，可能超过阈值。
- flush 不是 fsync，更不是掉电保证；先停完生产者，再 stop 唤醒、排空、join、关文件。
- 不支持依赖任意并发 start/stop/log 的生命周期；不能持队列锁等待消费者 join。

**10-03**
- CAN：`car存在 && connected && age < 3000`；相机：`camera存在 && running && age < 2500`。
- 媒体：`media存在 && healthy`；CAN 不活为 Emergency，否则相机或媒体不活为 Degraded，否则 Normal。
- 3000/2500 的等号边界均失效；媒体初始化成功后空闲也可能健康，不要求正在播放。

**10-04**
- P0—P6 依次为 Normal、Normal、Degraded、Emergency、Emergency、Degraded、Normal。
- 状态信号在 P2/P3/P5/P6 发出，共 4 次；诊断在七次 poll 均发出，共 7 次。
- 本批结束大小为 10,485,900 字节；旧 `.1` 删除，新 `.1` 为该大小，当前文件重开后为 0 字节。
- 以上依赖题设中文件操作全部成功；实现没有完整的轮转失败恢复，不能将算例推广为保证。
- start 立即 poll；默认 2000 ms 周期要等下一次采样，GUI 阻塞会延迟，墙时钟调整也影响 age。

**10-05**
- 恰好保留 A-WARN、A-ERROR、B-WARN、B-ERROR 四条；A-INFO/B-INFO 均不入队。
- A 的 WARN 早于 A 的 ERROR，B 同理；跨线程没有固定序，时间戳也不应用作全序断言。
- 关键思路是每轮隔离目录、唯一标记、集合加计数断言、先 join 两生产者再 stop 后读文件。
- 比较去除时间前缀后的消息即可；仅看到路径、退出码或恰好四条旧日志不能得证据分。

**10-06**
- 以纯输入表测试时，应保留存在性检查和严格小于；不要由真实 sleep 构造精确毫秒边界。
- 其余服务健康时：缺 CAN 为 Emergency；缺相机、缺媒体、相机 running=false 均为 Degraded。
- 两个阈值的等号必须失败；CAN 失败应压过相机/媒体失败，通知计数沿用 10-04。
- 暂停帧输入而不停采样，后续 age 达阈值时进入 Emergency；不承诺真实 3 秒整告警。
- diagnosticsChanged 不会自动落盘；判定副本通过不等于仓库已有 HealthMonitor 专项测试。

**10-07**
- A：核对 stderr、实际文件追加和工作目录；start 返回 void，失败可能保留旧路径，fallback 为进程 cwd/logs。
- Qt handler 路由到日志文件；不要在 handler 内用 qWarning 报自身错误，避免递归；Fatal 异步入队也不保证写出。
- B：核对队列增长、生产者生命周期与存储阻塞；无界队列和持续产生日志都可能拖慢退出，先让生产者停止。
- C：模拟器直接进 onCanFrame，不经 SocketCAN 计数；首帧前立即 poll 可短暂 Emergency。
- 后续 CAN 新鲜但相机失败应为 Degraded；检查相机输入/插件证据，不能用 frames:0 判模拟器已停。

**10-08**
- 四阶段应为 Normal→Degraded→Emergency→Normal；恢复阶段必须重新满足三项输入条件。
- 对照实际采样次数计算信号，而非把每条日志当一次状态变化；诊断日志须有显式桥接。
- 正常停产再 stop 只支持该生命周期下的排空；Ctrl+C、SIGTERM、kill -9、qFatal 或掉电不是相同证据。
- 记录墙时钟、批后轮转、无界队列与硬件待验边界；把未测内容标为待验可得范围分，编造通过不可得证据分。
