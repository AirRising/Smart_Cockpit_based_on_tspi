# 开发指南配套练习 · 源码综合题

[对应开发指南](../DEVELOPMENT.md) · [题集导航](README.md)

**前置**：先完成对应章节练习，再使用开发指南查源码。建议 2～4 小时，可分两次完成。产物放在 `$WORK/exercises/development`。共 8 题，100 分，题号使用 `DEV-01`～`DEV-08`。

这套题不是第 14 章的又一次毕业工程，而是训练“沿着入口找实现、沿着实现找证据”。不得只背类名；答案应写实际文件、函数和当前可核对的位置。行号可能变化，记录时自行核对，不猜行号。

## 基础与推演

### DEV-01 找到职责真正归属（5分）

给下列任务各找一个主要实现位置，写文件与函数或类名：

1. 纯 C++ 的位布局与字节解析。
2. Qt 容器到纯 C++ 容器的适配。
3. 收帧后的字段完整性检查及车辆状态更新。
4. 普通页与倒车页的优先级仲裁。
5. Qt 日志消息进入标准库日志队列。

**提交与评分**：每项位置与职责说明完整得 1 分。不要把所有任务都归给 MainWindow。

### DEV-02 画的是上下文，不是固定线程总数（5分）

为 GUI、SocketCAN 接收、GStreamer 样本转换、日志写盘四类工作分别写执行上下文，并解释为什么不能据此断言操作系统里恰好只有四个线程。

**提交与评分**：四类各 1 分，内部线程边界说明 1 分。

### DEV-03 为结论配证据（5分）

分别给以下结论找“实现位置 + 测试或手工验证方法”：

- 截断帧不会覆盖旧输出。
- 取消空调请求会停止相应等待。
- 相机停止后旧轮次帧不能重新覆盖清屏状态。
- 未找到 bus 消息时，媒体位置查询可能被提前返回跳过。
- 声称板上显示正常，需要在板上实测。

**提交与评分**：每条 1 分；对现有测试没有覆盖的项目，写“需增加/需实测”，不能捏造已存在的测试。

### DEV-04 分开画两种上行和一种下行（15分）

画三条路径，并在跨线程箭头上标出 queued 边界：

1. `0x100` 仪表帧从 socket 到速度显示。
2. `0x300` 的首字节 `03` 从 socket 到 R 挡标签与倒车页请求。
3. 温度控件改变，从 250ms 防抖到本地请求、线上 ACK、通知 UI 或 600ms 超时。

第三条必须分别标出“本地受理”“尝试写总线”“收到匹配 ACK”。解释为什么不能把 0x100 的速度数据也当作倒车来源，或把本地 requestId 画进当前 CAN 报文。

**提交与评分**：三条各 4 分，帧类型及受理/传输/确认的区分 3 分。

## 动手实践

### DEV-05 做一份源码检索地图（20分）

实际打开对应源码，建立下列六条检索记录，每条包含：文件与符号、调用方、状态改变或副作用、下一步观察位置。

- `CarService::onCanFrame`
- `CarService::sendClimateCommand`
- `CarService::cancelClimateCommand`
- `CameraService::handleSample`
- `CameraService::stop`
- `AsyncLoggerCore` 的消费循环与停止逻辑

不要把整段源码复制为答案；每条用自己的话描述 3～5 行。任选一条再追到实际测试断言，并说明该断言没有覆盖什么。

**提交**：带可核对定位的检索表。此题是只读实践，不需要运行或修改设备。

**验收与评分**：六条准确定位与关系各 2 分，共 12 分；状态/副作用说明 4 分；测试证据与边界 4 分。

### DEV-06 追踪一次“按了取消”（20分）

在第 07 章的本地服务实验或自己的 UI 测试中，受理一个 24℃、风量 5 的请求，然后取消：

1. 保存非零 requestId，证明取消操作针对该请求。
2. 观察取消信号、pending 清理；等待超过原请求超时窗口，证明不会再收到该请求的 timeout。
3. 在空闲时注入该目标的迟到 `ack=true`，检查不会凭空创建新确认。
4. 再启动 28℃的新请求，用旧 24℃ ACK 和匹配 28℃ ACK 分别检查结果。

所有帧只直接注入测试中的服务，不打开真实 CAN。不把“不同目标旧 ACK 可过滤”扩展为“同目标旧 ACK 也必能过滤”。

**提交**：事件序列、信号的 ID/数量、状态记录、对应源码位置；若加入 UI，额外记录取消后输入恢复和新请求发起。

**验收与评分**：精确 ID 与取消 5 分，停止超时 5 分，两种迟到 ACK 行为 6 分，证据来源与协议限制 4 分。

## 排障与综合

### DEV-07 审核一份过度乐观的说明（15分）

下面六句都有问题。逐句改写，并为其中三句定位源码或配置依据：

1. “QImage 注册为元类型后，在任意线程改同一个图像都安全。”
2. “CAN 的发送有锁，因此接收计数也一定线程安全。”
3. “使用 QOpenGLWidget 和 io-mode=4，所以摄像头是零拷贝。”
4. “程序总在后台运行，所以媒体切换只改 URI 就足够。”
5. “部署服务会自动重启，所以相机断流也会自动重连。”
6. “原部署文件可以直接在任意 ARM 板上运行。”

**提交与评分**：六项纠正各 2 分，共 12 分；三项准确定位各 1 分。区别“进程重启”与“应用仍存活时单个流恢复”。

### DEV-08 提交一个跨模块变更提案（15分）

仅做设计，不修改真实车辆协议：在自己的隔离教学工程增加“左前门是否打开”。选择一个尚未占用的标准帧 ID 和单比特布局，给出完整变更清单：

- 数据结构/内置核心表、外部 DBC、CarService 分发与状态/信号。
- 模拟输入、页面显示、测试和文档。
- 两条已知字节答案，重复帧、截断、缺字段定义的处理。
- 若另加一个诊断页，怎样注册和保持普通优先级，为什么不能为方便就抢占倒车。

如果学习副本已经用 `0x500` 表示冷却液温度，必须选择其他未占用 ID；不得用同一个 ID 表示两个互不兼容的定义。

**提交与评分**：跨层文件/接口清单 6 分，协议与测试答案 5 分，页面优先级和隔离范围 4 分。不要求完整实现这一额外扩展。

**DEV-04**：socket 接收经 CanManager::frameReceived 的显式 queued 连接进入主线程 CarService；0x100 经解析/字段守护/状态变化信号到仪表，0x300 首字节 03 同时表示倒车 bit 和 R 挡编号，触发相关状态与 MainWindow 的倒车页面请求。空调在 UI 防抖后请求服务，非零 ID 仅表明本地接受；发送失败仍可能进入等待。0x200 匹配五字段且 ack=true 才确认 pending，不匹配继续等待。当前线上没有本地 ID。

**DEV-05**：至少追清 onCanFrame 的帧分发、命令的 pending/定时器、取消的 ID 校验/停 timer/通知、相机样本的转换和 queued 代际检查、stop 的清理与空帧、日志生产消费与 join。不要混淆对象所属线程与函数当前执行线程。测试只证明它断言过的输入/时序，不证明所有竞争都不存在。

**DEV-06**：A 取消后不再产生 A 的超时；空闲迟到 ack=true 被忽略；B 目标 28℃ 时收到 24℃ ACK 不确认，收到五字段匹配的 28℃ ACK 才确认 B。计数必须连同 ID 验证，不只看“有一次信号”。负向等待需覆盖原超时窗口并处理事件，不能阻塞事件循环后声称 timer 没触发。

**DEV-07**：

1. 元类型注册支持传递，不是任意共享修改的同步机制；当前按值捕获图像、转换后不再写入。
2. 发送锁不保护所有字段；[CanManager.h](../../src/core/CanManager.h) 的普通接收计数仍有跨线程同步缺口。
3. [CameraService](../../src/camera/CameraService.cpp) 做 CPU 像素转换和图像分配，GL 显示不能自动消除拷贝。
4. MediaService 在 PLAYING 时仅换 URI 有已知问题，还需检查 GStreamer 状态转换和实际音频来源。
5. systemd 重启进程不同于运行中 cameraError 后的流恢复；当前服务无自动重连。
6. 工具链、目标库、root/设备权限、KMS connector/mode、目录和真实摄像头参数都需适配；模板不能等同于通用部署器。

**DEV-08**：示例可选学习副本未占用的 `0x501`，Intel `0|1` 无符号、系数 1、偏移 0；其余位为 0，则关闭/打开的完整八字节分别为 `00 00 00 00 00 00 00 00` 与 `01 00 00 00 00 00 00 00`。该布局至少需 1 字节，截断边界是空 payload，不是“少于八字节一律错误”。服务须查所需字段存在，重复状态不重发；UI 不重新解码。新增普通诊断页不应为了易见而高于倒车优先级。其他 ID/位段方案也可得分，但需独立算对字节、不冲突，并列出完整连接与测试。
