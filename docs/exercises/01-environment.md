# 01 配套练习 · 环境准备与第一次运行

[对应教程](../01-environment.md) · [题集导航](README.md)

**前置**：读完教程 01，能打开 Linux 终端。建议 60～120 分钟，不计安装依赖的时间。作业放在 `$WORK/exercises/01`；变量与提交格式见题集导航。共 8 题，100 分。

本套重点是分清“工具可见、配置成功、编译成功、测试通过、界面可用”五件事，不要求修改业务代码。缺少桌面或依赖时提交诊断和待执行计划，不能填造运行结果。

## 基础与推演

### 01-01 工具各负责哪一步（5分）

把下列任务分别交给 g++、CMake、Qt Widgets、GStreamer、CTest，并说明理由：

1. 生成构建规则。
2. 编译并链接 C++。
3. 创建按钮并处理点击。
4. 解码音视频数据。
5. 按注册清单执行测试程序。

**提交与评分**：一张配对表，每项正确 1 分；不要把 CMake 写成编译器。

### 01-02 三个目录不能混（5分）

假设 `PROJECT=/home/learner/reference`、`HOST_BUILD=/home/learner/build/cockpit`、`WORK=/home/learner/lab`：

- 参考源码、目标文件 `.o`、自己的第二章窗口代码分别应该在哪一类目录？
- 打开新终端后，三个变量还一定存在吗？为什么不把唯一一份手写代码存进构建目录？

**提交与评分**：目录归属 3 分，变量作用域与源码保护各 1 分。

### 01-03 通过了一步能承诺什么（5分）

判断正误并各用一句话说明：

1. `pkg-config` 找到 Qt，说明窗口必定能显示。
2. `gst-inspect-1.0 appsink` 成功，说明真实摄像头必定可用。
3. 六项测试通过，说明这些用例通过，但不是没有其他 bug。
4. `--sim` 会自动模拟空调控制器的 ACK。
5. 摄像头不传设备路径，与是否启用 `--sim` 是两个独立选择。

**提交与评分**：每项判断及理由均正确得 1 分。

### 01-04 给错误划分阶段（15分）

以下是五条**供阅读的示例诊断，不必故意破坏开发机复现**：

```text
A. Could not find Qt5WidgetsConfig.cmake
B. fatal error: QLabel: No such file or directory
C. undefined reference to sc::CarService::start(...)
D. Could not load the Qt platform plugin "xcb"
E. No tests were found!!!
```

对每条写出：发生阶段、首个检查对象、为什么不能直接宣布成功。E 假设出现在刚配置的空构建目录，不是在已核对过的六测试构建中。

**提交与评分**：每条 3 分。检查对象应具体到依赖、目标源文件/链接库、显示会话或测试注册，而不是统称“重装软件”。

## 动手实践

### 01-05 制作可复查的环境记录（20分）

只使用教程中的只读检查命令，记录：

- 系统与架构；编译器、CMake、Qt5 Widgets 和 GStreamer 的实际版本。
- `videotestsrc`、`appsink`、`playbin`、`alsasink` 是否可见。
- 是否有可用桌面会话；是否具备音频设备、ARM SDK、摄像头。
- 与 C++17、Qt 5.15、CMake ≥3.21 学习基线的差异。

不要求为了完成本题立即安装缺失依赖，也不要求修改环境变量掩盖诊断。

**提交**：环境表和必要的原始输出；缺失项写清现象与下一步。

**验收与评分**：版本及架构 8 分，插件检查 4 分，条件与差异记录 4 分，能区分开发包/运行时插件/设备可用性 4 分。

### 01-06 在参考源码外完成一次构建（20分）

先检查所选构建目录是否已有重要内容，再按教程完成 Debug、Qt5、测试开启的配置与构建。保留以下证据：

1. 实际使用的 `-S`、`-B` 和配置选项。
2. 构建结果；若失败，停在首次错误处分析，不继续运行旧程序充数。
3. 对同一构建目录运行 CTest，写出发现的测试数、通过数、失败数。
4. 解释为什么不能拿另一个 `build/debug` 目录的结果代替本次构建。

**提交**：构建与测试记录，不需要复制二进制到参考仓库。

**验收与评分**：目录与配置 5 分，构建证据 5 分，测试数量和结果 5 分，失败/版本/目录差异分析 5 分。环境阻塞时提交精确诊断和待执行命令，注明本题未完成实跑。

## 排障与综合

### 01-07 模拟模式里的三个“异常”（15分）

同学报告：仪表会动，但 socket 接收计数为 0；调整空调后回滚；经 SSH 启动程序看不到窗口。请分别回答：

- 现象是否足以证明代码 bug？
- 对应的数据来源或环境前提是什么？
- 下一项最小验证应该做什么？

**提交与评分**：每个现象 5 分。不得用“整个 GUI 改用 root 运行”作为通用解法，也不能说 CAN 打不开会自动启动模拟器。

### 01-08 写一张诚实的首次验收单（15分）

在自己的桌面运行模拟模式，或无桌面时完成等价的检查计划。验收单至少包含：

- 仪表变化、普通页切换、模拟倒车期间的页面优先级。
- 摄像头测试源画面与真实摄像头的区别。
- 空调请求超时的预期、日志目录和正常关闭方式。
- 实际完成项与缺条件项分别列出。

不得将 `Ctrl+C` 等同于窗口关闭后完成全部清理；不要求连接车辆。

**提交与评分**：场景与预期 6 分，实际证据或明确待执行步骤 6 分，验证边界 3 分。

## 参考答案

<details>
<summary>参考答案与评分提示（先独立完成）</summary>

**01-01**：依次为 CMake、g++、Qt Widgets、GStreamer、CTest。Qt Test 写断言和测试类，CTest 组织执行，二者也不能混为一谈。

**01-02**：参考源码在 PROJECT；`.o` 在 HOST_BUILD；自己的代码在 WORK。普通 shell 变量只属于当前 shell 环境，新终端需重新设置。构建目录可被重新生成，不应承载唯一源码。

**01-03**：依次为错、错、对、错、对。包描述文件、运行时元素、硬件与显示会话是不同层；模拟器只注入 0x100/0x300/0x400，不生成空调 ACK；空设备路径独立选择测试视频。

**01-04**：

- A：CMake 配置阶段；查 Qt 开发包、包搜索路径与版本。
- B：编译阶段；查开发头文件和当前目标的 Qt 依赖/包含路径。
- C：链接阶段；查对应实现是否编入目标、签名是否匹配、所需库是否链接。
- D：运行初始化阶段；查有效桌面会话、Qt 库与插件版本、插件依赖，不直接切 eglfs。
- E：测试发现阶段；查正确构建目录、`BUILD_TESTING`、`enable_testing`/测试注册。零项测试不等于六项通过。

**01-05**：记录实际值，不抄参考机器版本。`pkg-config` 成功不保证插件存在，插件存在不保证设备和权限可用；同样，设备节点存在不代表支持所需格式。缺失项有明确诊断也有学习价值。

**01-06**：应能从命令还原构建来源；参考项目在启用测试后注册六套测试。发现数不是六时先核查目录与配置，而不是填写“全部通过”。失败后保留最早有效诊断，不能把前一次产物当成本次成功。

**01-07**：

1. 模拟帧直接注入 CarService，不经过 CanManager 的接收计数；比较数据入口而不是凭计数判定仪表是假数据。
2. 模拟器不回 ACK；服务接受请求后约 600ms 未确认会超时。之后可用第 07 章受控帧注入验证 ACK 成功路径。
3. SSH 可能没有有效显示会话；先确认桌面、授权和 Qt 平台环境。可以先做离屏普通控件/服务测试，但不能声称视频窗口已验收。

**01-08**：倒车发生在每轮 `45≤t<52` 的模拟时间，GUI 忙时不保证精确对应墙钟时间；普通请求不能抢占倒车页。测试球证明测试源链路，不证明 V4L2 摄像头正常。正常关闭窗口可使 `app.exec()` 返回；日志需核对实际文件位置。验收单不能把计划中的项目写成实际通过。
