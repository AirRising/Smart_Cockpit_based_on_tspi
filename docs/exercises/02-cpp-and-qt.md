## 基础与推演

### 02-01 值、引用和指针（5分）

只阅读下面的 C++ 片段，写出最后 `a`、`b`、`alias` 和 `*pointer` 的值，并解释为什么不是四个独立整数。

```cpp
int a = 8;
int b = a;
int &alias = a;
int *pointer = &a;
b += 2;
alias += 4;
*pointer -= 1;
```

**提交与评分**：四个数值各 1 分，解释共享同一个对象 1 分。

### 02-02 信号是不是新线程（5分）

针对本章窗口回答：

- 按钮、QTimer、标签目前分别由哪个线程操作？
- `clicked` 连接到 lambda 后，是否自动出现新线程？
- 为什么 `app.exec()` 长时间不返回通常不是卡死？
- 若槽函数一直做计算，为什么按钮和重绘都可能延迟？

**提交与评分**：线程归属 2 分，其余三问各 1 分；回答需联系事件循环。

### 02-03 谁负责销毁，谁只是借用（5分）

列出本章 `window`、`timer`、`label`、`button` 的创建方式与销毁责任，并解释为什么 lambda 的 `context=&window` 不能保证任意捕获的局部变量永远有效。

**提交与评分**：四个对象各 1 分，捕获生命周期 1 分。不能只写“Qt 都会自动处理”。

### 02-04 按事件而不是按秒算速度（15分）

以下假定每个事件按列出的顺序执行，没有额外 timeout。初始 `speed=119`、`running=false`，每个运行中的 timeout 执行 `(speed+1)%121`：

```text
timeout → 点击开始 → timeout → timeout
→ 点击暂停 → timeout → 点击开始 → timeout
```

逐项填写事件后的 speed、running、按钮文字。再说明为什么“等待 1 秒必定处理 10 次 timeout”不是严格成立的结论。

**提交与评分**：8 行状态表 12 分，计时边界解释 3 分。

## 动手实践

### 02-05 复位按钮不负责暂停（20分）

从本章完整窗口例子建立自己的学习副本，添加“复位”按钮：

1. 按钮加入布局，不使用固定屏幕坐标。
2. 点击后速度和标签立即变为 0。
3. 保持点击前的 running 状态，开始/暂停按钮文字仍一致。
4. 已为 0 时再复位不能让速度意外前进。

验收三种情形：暂停在非零值时复位；运行时复位；暂停在零时连续复位。运行中复位后**下一个** timeout 可以使速度变为 1，不要求它永远停在零。

**提交**：源码、构建命令和三个操作记录。

**验收与评分**：正确改变状态 6 分，即时显示 4 分，保留运行状态 4 分，布局与所有权 2 分，三种证据 4 分。

### 02-06 增加阈值提示，但保留真实数值（20分）

继续上一题，在速度标签之外新增一个提示标签：

- `speed > 100` 显示“请减速”，否则显示“正常”。
- 原速度标签始终显示数字与 `km/h`。

为定位边界，可以在自己的实验中暂时设置初始值为 99；不要等很久后凭印象填结果，也不要留下另一份与 speed 不一致的“提示速度”。

**验收与评分**：阈值 5 分，数字保留 3 分，两条更新路径与初值 6 分，六个边界证据 6 分。

## 排障与综合

### 02-07 “地址还在”为什么仍然错误（15分）

下面是**只用于审查的错误片段，不要实际运行悬空引用**：

```cpp
void wireButton(QPushButton *button, QWidget *window)
{
    int count = 0;
    QObject::connect(button, &QPushButton::clicked, window, [&count]() {
        ++count;
    });
}
```

假定函数返回后窗口和按钮仍存活，用户此时才点击：

1. 哪个对象已经失效？窗口作为 context 为什么没解决？
2. 把捕获改成 `[count]`，为什么不能简单等同于更新外部共享状态？
3. 给出一种安全的生命周期设计，并写出你如何检查它。

**提交与评分**：失效原因 6 分，值捕获语义 3 分，安全设计与检查 6 分。

## 参考答案

<details>
<summary>参考答案与评分提示（先独立完成）</summary>

**02-01**：`a=11`、`b=10`、`alias=11`、`*pointer=11`。b 是初值副本；alias 与 pointer 均访问 a。

**02-02**：这些对象都在 GUI 主线程；本例默认连接通常直接执行 lambda，不会因信号而创建线程。事件循环要持续等待并分发事件；耗时槽占住主线程会推迟其他事件，设置一个较短的 QTimer 间隔不能消除阻塞。

**02-03**：window、timer 是栈对象，离开作用域后析构；label、button 在堆上创建，作为 window 的子对象由其销毁。连接上下文销毁会断开连接，但不延长其他被引用局部变量的寿命。教程把 speed/running 定义在 window 之前，使它们在 window 之后析构。

**02-04**：

| 事件 | speed | running | 按钮 |
| --- | --- | --- | --- |
| timeout | 119 | false | 开始 |
| 点击开始 | 119 | true | 暂停 |
| timeout | 120 | true | 暂停 |
| timeout | 0 | true | 暂停 |
| 点击暂停 | 0 | false | 开始 |
| timeout | 0 | false | 开始 |
| 点击开始 | 0 | true | 暂停 |
| timeout | 1 | true | 暂停 |

100ms 是请求的计时间隔，事件循环、系统调度和忙碌会影响实际处理时刻；应按已处理事件推演，而不是把墙钟等待当成精确计数。

**02-05**：复位必须同时改变唯一的 speed 与对应显示，不改变 running；仅把标签写成 0 是假复位，下一个 timeout 会暴露旧值。点击复位不应主动执行一次“加速”，也不应偷偷停止 timer。

**02-06**：0/100 正常；101/120 提示“请减速”；120 后回绕为 0，提示恢复正常。提示时复位也应恢复正常。可以用一个局部刷新函数统一两个标签的计算；关键是所有状态改变路径都刷新，不能为了显示提示复制另一份状态源。

**02-07**：函数返回后 count 已结束生命周期，context 仍存活不代表 count 有效。`[count]` 捕获副本，普通 lambda 默认还不能修改该副本；加 `mutable` 也只改变闭包自己的值，不等于修改已不存在的原变量。可以将计数放在比连接活得更久的对象成员里，并用该 QObject 作为 context；或在主函数中让状态先于窗口创建、晚于窗口销毁。检查创建/销毁顺序以及所有引用捕获，而不是依赖栈地址偶尔未被覆盖。

**02-08**：本章只使用 Qt 已有元对象类并连接 lambda，没有自定义信号，因此不必自己声明 Q_OBJECT。拆出自定义 QObject 服务和信号后需 Q_OBJECT、AUTOMOC 及正确的源文件/头文件目标配置；窗口转为观察状态而不是拥有各自的速度副本。
