## 题目

### 04-01 先分清 ID、长度和数值（5分）

输入：一条标准帧，ID 写作 `0x100`，payload 为 `B8 0B`，DLC 为 2。
把整个 payload 暂作一个从 bit0 开始的 Intel 无符号 16 bit 信号。

需提交：ID 的十进制值、payload 的字节数与位数、该信号的原始十进制值，并写出算式。
另回答“标准 ID 占用了这两个 payload 字节中的几个”“classic CAN 最多允许多少 payload 字节”。
约束：不能把 ID 拼到 payload 前面一起计算；DLC 指本帧数据长度，不是固定等于最大长度。
验收/评分：ID 1 分，字节/位数 1 分，数值及算式 1 分，ID 与数据区关系 1 分，最大长度 1 分。

### 04-02 读懂一条协议声明的职责边界（5分）

输入：以下是 DBC 信号行片段，非完整 DBC 文件；假定其所在 BO_ 已正确声明。

```dbc
 SG_ angle : 7|16@0- (0.1,-2) [-900|900] "deg" ECU
```

需提交：把名称、起始位/位长、端序/符号、factor/offset、范围/单位整理成五组注释。
在最后一组中说明：参考解析器是否会因为计算结果超出这个范围而自动拒绝解码。
约束：起始位含义必须说到“信号的最高或最低有效位”，不能只写“大端”二字。
验收/评分：每组 1 分；将范围当成已经执行的业务 clamp 不得该组分。

### 04-03 返回零与返回失败是一回事吗（5分）

输入：调用者 A 用 `decodeSignal()` 得到 `0.0`；调用者 B 用整帧 `decode()` 得到 `false`，调用前 out 中有旧值。
另有调用者 C 声称“物理量用 double 存储，因此任意 64 bit 原始整数都能精确往返”。

需提交：为 A 列出两种不同解释；写出 B 的旧 out 应如何变化；判断 C 的承诺及其精度依据。
约束：按教程当前接口分析，不擅自把单信号返回类型改成 bool；不运行越界浮点转整数实验。
验收/评分：A 的歧义 2 分，B 的保留语义 1 分，double 通常 53 位整数精度及限制 2 分。

### 04-04 画出真正的跨字节位路径（15分）

输入：下表前三行编码到全零的最短缓冲区；未特别指定时为无符号、factor=1、offset=0。
第四行做解码。分别标出“按顺序访问哪个字节的哪个 bit”和每一步的位权。

| 行 | 布局 | 输入 | 需计算 |
| --- | --- | --- | --- |
| A | Intel `7\|2` | 原始值 3 | 最少字节数、编码字节 |
| B | Motorola `0\|2` | 原始值 3 | 最少字节数、编码字节 |
| C | Motorola `7\|16` | 原始值 4660 | 最少字节数、编码字节 |
| D | Intel `0\|16`，signed，factor=0.1 | 字节 `9C FF` | 无符号读数、补码值、物理角度 |

需提交：逐位草图和四行计算表；D 必须写出符号解释与比例变换两个独立步骤。
约束：不得用“把整帧反转”代替 Motorola 遍历规则；前三行只输出必要字节，不补成固定 8 字节。
验收/评分：A 4 分，B 4 分，C 3 分，D 4 分；只有字节答案而无位路径最多取得该行一半分。

### 04-05 实现单信号的边界检查表（20分）

输入：只读复用 [Core 接口](../../src/core/CanFrameParserCore.h) 与 [Core 实现](../../src/core/CanFrameParserCore.cpp)。
在自己的 `signal_cases.cpp` 中实现表驱动检查，不能只验证“编码后再解码等于输入”。

需覆盖以下输入，并在代码中保存独立手算的期望字节：

1. Intel `7|2`、Motorola `0|2` 各编码 1、2、3；每例从空向量开始，解码也需核对。
2. 两种布局分别从已有缓冲区 `54 2A` 编码 3，检查信号之外的位没有被清零。
3. 非法布局 `start=-1,len=1`、Intel `63|2`、Motorola `0|58`、`start=0,len=0`。
4. 第 3 组每例都使用一个预先填满 `A5` 的 16 字节向量，保存快照后调用 `encodeSignal()`。

约束：非法 classic CAN 布局不能因输入缓冲区较大而变合法；factor 均为 1，不涉及浮点极值。
需提交：用例表、检查入口、编译命令与输出；出错需显示用例名，最终返回非零。
可按教程的 g++ 命令编译自己的入口与只读 Core.cpp；若使用 assert，不得定义 `NDEBUG`。
验收/评分：六个独立黄金字节检查 8 分，保留无关位 4 分，非法布局与不改输出 6 分，诊断及构建记录 2 分。

### 04-06 实现整帧输出保护与 DBC 覆盖实验（20分）

输入：新建内置解析器 A；好帧为 `78 00 B8 0B 64 01 00 00`，ID 为 `0x100`。
创建 out 并预填 `sentinel=42`。按顺序解码：完整 8 字节、前 7 字节、前 6 字节、前 2 字节、未知 ID `0x555` 的 8 字节。

需提交第一组检查：每次 bool、成功时 speed/rpm/fuel、失败时 out 与调用前快照是否相等。
成功后还要检查 sentinel 被清除，避免把“失败保留”误做成“永远追加而不清空”。
第二组另建解析器 B，在学习目录创建仅含如下两行的 DBC 输入：

```dbc
BO_ 256 Lab: 8 ECU
 SG_ speed : 0|16@1+ (1,0) [0|10] "km/h" ECU
```

加载后依次用 `C8 00` 与 `C8` 解码 0x100，核对字段集合、值与失败后的旧输出。
约束：本题刻意比较“内置布局”和“覆盖后的布局”；不把 BO_ 的 8 当成强制 DLC，也不期待自动范围校验。
需提交：`frame_cases.cpp`、DBC 输入、两组结果表与可重复的编译/运行命令，全部位于练习目录。
验收/评分：成功数据与清旧表 5 分，内置最小长度及失败保留 6 分，覆盖后的字段/范围/长度 6 分，记录清晰 3 分。

### 04-07 评审一次失败加载后的错误恢复（15分）

输入：一次加载的已知执行记录如下；后续错误已明确返回 false，不是被忽略的未知行。

1. 解析器原来使用内置表；已读到同 ID 的 `BO_ 256`，清空了该 ID 的旧信号表。
2. 已成功加入一条 Intel `0|16` 的 speed，factor=1、offset=0。
3. 后续解析报错，加载返回 false；调用者继续使用原解析器，声称“失败自动恢复默认”。

另有两条评审意见：“单信号结果为零就丢弃”“用 9007199254740993 做 double 精确往返的验收”。
需提交：加载后 0x100 的有效字段推断、输入 `C8 00` 的整帧结果，以及一个不改 Core 的安全加载流程。
再分别构造零值歧义反例、说明大整数验收为什么不可靠；本题假定 double 为通常的 53 位有效二进制精度。
约束：安全流程是你新增的调用侧目标，不是参考解析器已有的事务保证；无需故意触发不安全的数值转换。
验收/评分：非事务状态及候选对象隔离方案 7 分，零值反例 4 分，精度边界与合理替代检查 4 分。

### 04-08 设计一个独立的小协议验收包（15分）

输入：为学习用 ID `0x555` 写 DBC，只含两个不重叠信号；不接车辆服务，也不发送总线。

- `speed`：Intel `0|16`，无符号，factor=0.5、offset=0，描述范围 0..100，单位 km/h。
- `angle`：Motorola `23|16`，有符号，factor=0.1、offset=0，描述范围 -900..900，单位 deg。

需提交：DBC 文本、字节布局图、测试矩阵和检查入口设计；矩阵至少包含下列五行的 bool、字段和值/字节期望。
1. 整帧编码 speed=36、angle=-10，再对照独立黄金字节解码。
2. 将该输出截为 4 字节和 3 字节，分别解码并核对失败输出保护。
3. 编码 speed=150、angle=0，验证描述范围与实际解码的关系。
4. 编码只提供 speed=36，观察没有提供的已知字段。
5. 在第 1 行输入映射增加未知字段 `debug=9`，比较输出是否变化。

约束：整帧 encode 输出与单信号最短输出不能混用；不能因 encode 返回 true 就宣称 debug 已被支持。
未运行时提交推导表和计划检查点，不能填“全部通过”；若运行，用自己的小入口而不是修改项目测试。
验收/评分：DBC 与不重叠布局 4 分，黄金字节和长度边界 4 分，范围/缺字段/未知名称矩阵 4 分，证据及失败保护 3 分。

## 参考答案

<details><summary>参考答案与评分提示（先独立完成）</summary>

**04-01**
- ID 为十进制 256；payload 是 2 字节、16 bit。Intel 值为 `0x0B×256+0xB8=11×256+184=3000`。
- ID 不占 payload 字节；classic CAN 数据区最大 8 字节，标准 ID 本身为 11 bit。

**04-02**
- 名称 angle；起始位 7、位长 16；Motorola、signed，起始位指向最高有效位。
- factor=0.1、offset=-2；范围 -900..900，单位 deg。物理值为有符号 raw×0.1−2，范围描述不自动执行拒绝或 clamp。

**04-03**
- 单信号 0.0 可能是合法零，也可能是非法布局/数据不足。单看这个返回值不能区分。
- 整帧返回 false 时保留原 out；先检查所有字段再清空输出。double 通常只有 53 位整数精度，且当前解码还有 int64_t 转换边界。

**04-04**
- A：byte0.bit7 为原始 bit0，byte1.bit0 为原始 bit1；至少 2 字节，结果 `80 01`。
- B：byte0.bit0 为原始最高位，随后 byte1.bit7 为最低位；至少 2 字节，结果 `01 80`。
- C：先 byte0 的 bit7..0，再 byte1 的 bit7..0，位权从 2^15 降到 2^0；至少 2 字节，结果 `12 34`，即 4660。
- D：`0xFF9C=65436`；16 位补码为 `65436−65536=-100`；乘 0.1 后为 -10°，不是 -100°。

**04-05**

| 布局 | 值 1 | 值 2 | 值 3 | 从 `54 2A` 编码 3 |
| --- | --- | --- | --- | --- |
| Intel `7\|2` | `80 00` | `00 01` | `80 01` | `D4 2B` |
| Motorola `0\|2` | `00 80` | `01 00` | `01 80` | `55 AA` |

- 四种非法布局均返回 false，原 16 字节 A5 向量长度与内容都不变。Intel `63|2` 和 Motorola `0|58` 都需要跨到第 9 字节，不能放宽到 16 字节。
- 满分实现同时检查 bool、黄金字节、解码值和原缓冲区快照；只做往返可能掩盖编码/解码同向出错。

**04-06**
- A 的结果依次 true、true、false、false、false；前两次 speed=120、engine_rpm=3000、fuel_level=50，sentinel 消失。
- 内置最后字段位于 bit50，因此最少 7 字节；后三次 out 均等于调用前快照，不清零、不留下半帧结果。
- B 的加载成功；`C8 00` 解码成功且只有 speed=200。`[0|10]` 不拒绝 200，BO_ 写 8 不阻止两字节输入。
- 随后的 `C8` 解码失败，out 仍只有 speed=200。两组必须使用独立解析器，以免覆盖污染“内置最小长度”的检查。

**04-07**
- 按给定记录，0x100 只剩 speed，没有恢复原表；`C8 00` 可整帧解码成功，得到 speed=200，其他原字段不在结果中。
- 调用侧可在新候选解析器上加载，成功且检查必需字段后才替换正在使用的对象；失败丢弃候选，原对象从未被加载修改。不能先破坏原对象再称“已隔离”。
- 例如合法 Intel `0|8` 解码 `00` 与同布局解码空缓冲区都可能返回 0.0，只有前者是有效零；改用整帧 bool 或独立验证布局/长度。
- 2^53=9007199254740992；2^53+1 不能精确表示为通常的 double，常见最近偶数舍入会落回 2^53。用安全小整数与独立字节核对，不以未定义/越界转换作为测试手段。

**04-08**
- BO_ ID 应写十进制 1365；speed 占 byte0..1，angle 从 byte2.bit7 开始，占 byte2..3。声明标记分别为 `@1+`、`@0-`。
- 第 1 行 raw 分别为 72、-100；整帧编码为 `48 00 FF 9C 00 00 00 00`，解码 speed=36、angle=-10；浮点比较应允许小误差。
- 第 2 行四字节足够，三字节失败且保留 out。不要因为整帧 encode 固定输出 8 字节而误判最短输入长度。
- 第 3 行输出 `2C 01 00 00 00 00 00 00`，解码 speed=150、angle=0，范围不自动限制。
- 第 4 行输出 `48 00 00 00 00 00 00 00`，angle 的零位解码为 0；第 5 行仍与第 1 行相同，debug 被忽略。
- 检查入口应逐项报告实际 bool/字段/字节，并在失败时返回非零；只看 encode 的 true 不足以证明业务输入全部被识别。
