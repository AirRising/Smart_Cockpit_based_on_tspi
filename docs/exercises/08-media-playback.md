## 题目

### 08-01 请求状态与实际状态（5分）

- 输入约束：服务已初始化，文件存在；依次调用 openFile、pause、play、stop、shutdown。
- 任务：写出每一步请求的 GStreamer 状态，并说明哪些步骤释放资源。
- 任务：判断 openFile 返回 true 能证明到哪一步，是否还必须调用 play 才首次请求播放。
- 学生提交物：状态转换表，区分“已请求／管线已进入／真实输出”。
- 验收/评分点：五个入口的状态 3 分，异步请求语义 1 分，资源释放边界 1 分。
- 作答边界：不得把 stop 与 pause 混为一谈，也不要根据按钮名称推断底层行为。

### 08-02 文件、URI 与列表身份（5分）

- 输入约束：文件路径 `/tmp/车内 音乐/A B.wav`，TAG title 为“旅途”；同目录另有 `notes.txt` 与子目录中的 `C.wav`。
- 任务：说明路径如何转 URI，列表显示内容、UserRole 和播放标题分别保存什么。
- 任务：查清目录来源优先级、过滤范围和扫描时机，判断哪些条目会进入当前列表。
- 学生提交物：数据流图和目录来源表；不要求真的创建这些文件。
- 验收/评分点：URI 构造 2 分，路径/标题分离 1 分，目录和扫描边界 2 分。
- 作答边界：只讨论本地文件，不扩展网络流；不要把 TAG title 当作打开文件的路径。

### 08-03 总线消息与周期查询（5分）

- 输入约束：依次遇到 ERROR、EOS、TAG、子元素 STATE_CHANGED、playbin 的 STATE_CHANGED，以及一次空 bus。
- 任务：说明各类消息应该影响哪些服务信号，哪些消息不能代表整体播放状态。
- 任务：沿当前 `pollBus()` 控制流判断 position/duration 查询是否每次 timer 都执行。
- 学生提交物：消息职责表和不超过 6 步的控制流图。
- 验收/评分点：四类消息职责 3 分，来源过滤 1 分，查询路径判断 1 分。
- 作答边界：依据可执行路径而非注释判断；不要假设 EOS 已实现自动下一首。

### 08-04 单位换算与同长曲目轨迹（15分）

- 输入约束：UI seek 目标 10000ms；查询 position=12345678900ns、duration=120000000000ns，整数除法按源码处理。
- 输入约束：A 的 `m_durationMs` 已为 120000；Stop 后打开同长 B，立即通知未知时长，但暂不改变该缓存。
- 输入约束：打开后第 200、400ms 轮询无消息；第 600ms 有一条可处理消息，位置查询返回 600000000ns，时长查询返回上述时长。
- 任务：计算 seek 纳秒值、查询回传毫秒值以及 UI 的分:秒显示；解释整数截断位置。
- 任务：按原版写出三次轮询是否查询、发出哪些 position/duration 信号及 B 的滑块范围变化。
- 学生提交物：单位换算表、缓存/信号/滑块事件表，不能只写“有 bug”。
- 验收/评分点：换算与显示 6 分，无消息路径 4 分，缓存和滑块推演 5 分。
- 作答边界：题设查询结果是假数据；不据此断言真实管线已成功换曲。

### 08-05 实践：建立无输出的文件与换曲请求模型（20分）

- 输入约束：在学习目录建立 FakePipeline，记录状态请求和 URI 设置；不创建真实 playbin，不调用音频输出。
- 测试输入：带中文/空格的路径、文件不存在、尚未 init，以及“已在播放 A 时请求 B”。
- 任务：实现最小路径/URI 转换与请求记录；对照原版 openFile 的返回值、标题通知及请求顺序。
- 任务：在学习版本设计异步换曲流程，用人工投递的状态完成事件推进；为失败和未完成转换设计断言。
- 学生提交物：模型或测试源、原版路径与建议路径的调用序列表、至少六条断言。
- 无硬件替代：用脚本标准库处理路径，普通对象模拟状态机；无运行环境提交源文件与纸面调用日志。
- 验收/评分点：URI/存在性边界 5 分，原版行为准确 5 分，异步换曲顺序 6 分，反例与证据标注 4 分。
- 编码约束：不得在 GUI 线程无限等待状态转换；不要杜撰原服务已有公开 sink setter。
- 作答边界：模型验证请求顺序，不证明 GStreamer 真正解码了 B；不得把建议流程描述为参考仓库已修复。

### 08-06 实践：把周期查询从消息处理中独立出来（20分）

- 输入约束：学习副本或独立模型，查询器可注入成功/失败结果；每 200ms 虚拟 tick，不产生真实音频。
- 测试输入：连续 5 次空 bus 且 position 依次 200/400/600/800/1000ms；一次查询失败；A/B 同为 120000ms。
- 任务：为原版与学习版各写测试，验证空 bus 时查询行为；学习版实现独立查询和新曲时长缓存失效。
- 任务：用 Stop→Open B 隔离直接换曲问题，检查未知时长到有效时长的通知；处理失败查询而不伪造新值。
- 学生提交物：测试源/脚本、至少六条断言、原版失败与学习版期望的对照表。
- 无硬件替代：以列表模拟 bus 和查询器；没有解释器则交完整输入/调用计数/信号序列的纸面执行记录。
- 验收/评分点：空消息独立查询 6 分，同长曲缓存失效 6 分，失败查询处理 4 分，对照与计数 4 分。
- 编码约束：不要制造无意义 TAG 消息来驱动进度；若排空 bus，说明如何避免消息洪水占满一轮。
- 作答边界：新增方案只属于学习副本；参考仓库的无消息进度与同长曲缓存问题仍须列为未修。

### 08-07 排障：有标题、有 PLAYING，却没有足够证据（15分）

- 输入约束：报告一为“播放 A 时开 B，标题变 B”；报告二为“位置停住”；报告三为“Stop 后开同长 B，时长为零”。
- 输入约束：另收到一份已有 CLI 记录，使用 `fakesink sync=true`，显示 PLAYING 后 EOS；本题不重新执行它。
- 任务：为前三个现象分别定位一个优先控制流检查及一项对照测试，再评估 CLI 记录证明了什么。
- 任务：说明 openFile 返回 false 但没有 errorOccurred 时，页面为什么仍应处理失败。
- 学生提交物：排障表与证据层级说明，明确区分现象、原因假设、待验证结果。
- 验收/评分点：三个已知缺陷各 3 分，fakesink 证据边界 4 分，失败返回值处理 2 分。
- 无硬件替代：以消息轨迹和调用日志定位；ALSA、音量、扬声器与实际 MediaService 结果标“未验证”。
- 作答边界：不建议通过安装驱动、切换设备或调高音量来替代当前可做的逻辑排查。

### 08-08 综合：制定一份不过度宣称的播放验收（15分）

- 输入约束：只拥有 05—06 的模型结果、原版源码和 07 的 fakesink 记录，没有实际音频设备测试。
- 任务：设计 A/B 换曲、暂停继续、seek、EOS、同长曲、空列表、拖动进度条的分层验收矩阵。
- 任务：每行写刺激、观察点、通过条件、当前证据与未验证层；标明哪些是已有行为、已知缺陷或学习版建议。
- 任务：比较观察器 Resume 直接 play 与 MediaPage 播放按钮的调用路径，说明为什么标题变化不足以验收。
- 学生提交物：至少七行矩阵，以及面向维护者的 150 字以内结论，不再实现完整播放器。
- 验收/评分点：场景与断言 6 分，服务/UI 边界 4 分，缺陷和证据范围 5 分。
- 无硬件替代：给出可复核的模拟事件与将来需采集的证据；听觉和真实设备测试一律保留“未验证”。
- 作答边界：现有 UI 绘制冒烟测试不能替代解码、换曲内容、ALSA 或听觉验收。

<details><summary>参考答案与评分提示（先独立完成）</summary>

**08-01**

- openFile 已请求 PLAYING；pause 请求 PAUSED；play 请求 PLAYING；stop 请求 READY；shutdown 停 timer、请求 NULL 并释放 playbin/bus。
- openFile 的非 FAILURE 返回只说明请求未立即失败，可能异步；再次 play 是当前页面的重复请求，不是首次播放的必要阶段。
- PLAYING 和 `healthy()` 均不能证明扬声器有声；stop 不是 pause，也不是资源全部释放。

**08-02**

- 用 `QUrl::fromLocalFile(path)`，不能直接拼 `file://`；编码后 URI 要能还原同一绝对路径，空格不能拆成参数。
- 列表显示文件名，UserRole 存绝对路径；初始标题取 completeBaseName，TAG 可把标题改为“旅途”，不改变文件身份。
- 非空 `--media-dir` 经 main 写入环境变量优先；否则用 `SMART_COCKPIT_MEDIA_DIR`，再回退 MusicLocation。
- 只在构造时扫描当前层 mp3/flac/wav/ogg，按名称排序；notes.txt 和子目录 C.wav 不入表，没有实时文件监视。

**08-03**

- ERROR 报错、置不健康与非播放，释放 error/debug；EOS 发非播放，没有自动下一首；TAG title 更新曲名并释放标签资源。
- STATE_CHANGED 仅 playbin 自身用于整体播放状态；子元素状态不能代替它。当前每轮最多取一条匹配消息。
- 当前空 bus 提前 return，后面的 position/duration 查询也被跳过；200ms timer 不等于200ms 必有进度回传。

**08-04**

- `1ms=10^6ns`；10000ms seek 为 10000000000ns，查询得到 12345ms 与 120000ms；显示分别为 00:12、02:00。
- 纳秒转毫秒丢弃不足 1ms 的余数，格式化再按整秒截断；不能把毫秒直接当纳秒，也不能两端重复放大。
- 打开 B 发 `durationChanged(-1)`，页面把滑块范围变为 0..0、时长显示 00:00；服务缓存仍为 120000。
- 200/400ms 无消息，均不查询，也无 position/duration 新信号；600ms 处理消息后查询，发 positionChanged(600)。
- 600ms 时长仍等于缓存，故不再发有效 duration；滑块仍为 0..0，设值被范围限制，时间标签按 600ms 仍显示 00:00。
- “停止再打开”只隔离 URI 切换问题，不能修复时长缓存；真正内容是否换成 B 不在这份轨迹的证据范围内。

**08-05**

- 检查存在性和 init 前提；失败直接 false，未必发 errorOccurred。有效路径通过 QUrl 转换；Python 替代是路径模型而非 Qt 实测。
- 当前 openFile 顺序为设置 URI/sink、更新标题、发未知时长、请求 PLAYING；播放中没有先退回可重建流状态，换曲仍有缺陷。
- 合格学习流程：请求 READY 或 NULL → 确认已到可换流状态 → 设置 B URI/重置新曲状态 → 请求 PLAYING → 等实际状态通知。
- 未收到状态完成事件前不得提前记为已切 B；转换失败保留失败证据，不继续伪造成功，不阻塞 GUI 线程无限等待。
- 测试至少覆盖中文空格往返、缺文件、未 init、正常打开、转换未完成、转换失败；路径名或标题断言不能替代内容断言。
- 原服务无公开 sink setter 或音频 sink 命令行开关；FakePipeline 是练习用适配器，不是现有接口。

**08-06**

- 原版 5 次空 bus 的查询次数与 position 信号数均为 0；学习版每次独立查询，成功时依次发 200/400/600/800/1000ms，共 5 次。
- position 或 duration 查询失败时不使用未定义结果、不伪造新信号；按被测查询分别统计成功与失败。
- 每次准备新曲需同步失效时长缓存，例如恢复未知哨兵 -1；B 查询到 120000 时应再次通知有效时长，即使与 A 相同。
- 预期新曲时长信号为 `-1 → 120000`；原版可能只有 `-1`。测试以 Stop→Open B 避免把两个缺陷混成一个。
- 控制流片段（伪代码，非完整实现）：`处理本轮有限消息; 查询位置; 查询时长并比较新曲缓存;`。
- 合格提交保留原版失败断言和学习版通过预期，不用额外消息“碰巧”触发查询，不声称参考源码已被修改。

**08-07**

- 标题变 B：先检查播放中直接设 URI 的顺序，用模型和将来的内容对照验证；标题只是 trackChanged，不能证明音频切换。
- 位置停住：检查 `if (!message) return`，用空 bus+递增查询器隔离；暂停时位置不增长不应判成同一故障。
- 同长 B 为零：检查未知时长通知与 `m_durationMs` 未重置，相同值比较会跳过有效通知；Stop 不能清除此缓存缺陷。
- fakesink 的 PLAYING/EOS 记录只证明该 CLI 测试文件的解码链；sync=true 按时间消费，不输出声音。
- 它未经过真实 MediaService，也未验证 ALSA、音量或扬声器；当前三个缺陷均不能凭此宣布修复。
- 未初始化/文件不存在可直接 false 而无错误信号；页面应单独处理返回值，不只等待 errorOccurred。

**08-08**

- 矩阵需覆盖：换曲看状态完成及内容；暂停/继续看真实状态与位置；seek 检查单位、底层成功与后续位置；EOS 不假设自动下一首。
- 同长曲看 `-1→有效时长`；空列表看路径/扩展名/非递归扫描和无项行为；拖动时看查询更新是否抢回用户滑块。
- 当前 MediaPage 的播放按钮走 openSelected→openFile→play；观察器 Resume 只 play，不能把两者等同于同一种恢复策略。
- 程序更新滑块有 `m_sliderSyncing`，用户释放才 seek，但查询更新尚未跳过 `isSliderDown()`；状态槽当前没有实际 UI 更新。
- 应列为原版未修：直接换曲、空消息进度、同长曲缓存；“独立查询/新曲失效/异步换曲”只能记学习版设计或模型结果。
- 总结应写逻辑模型通过的范围，真实服务、解码集成及音频硬件仍未验证；不能由 fakesink 或 offscreen 绘制推得真实有声。
