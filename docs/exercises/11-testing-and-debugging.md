### 11-01 六套测试不是六个断言（5分）

**输入/约束：** 阅读测试注册，按纯 C++、解析适配、相机、空调、页面调度、UI 六个职责寻找入口。
区分 CTest suite、Qt 测试函数和数据行；不要把配置失败后的“零测试”当通过。

**任务：** 写出六个 CTest 名称及各自重点；指出哪三个由 CTest 设置 offscreen，哪个不能用 Qt 函数筛选语法。
解释纯 C++ 目标不链接 Qt，为何不代表顶层 CMake 配置无需 Qt/GStreamer。

**提交物：** 六行映射表，附 suite/函数/数据行区别及配置依赖说明。

**验收/评分点：** 六个名称与职责 3 分；层级与筛选边界 1 分；offscreen 和顶层依赖边界 1 分。

### 11-02 手算独立线上字节（5分）

**输入/约束：** DBC 信号为 Motorola `0|2@0+`，factor=1、offset=0、值=3，初始所有字节为零。
只按位序推导，不调用编码器或解码器生成“预期”。

**任务：** 标出两个值位落在哪个字节的哪一位，写最小字节序列和整帧八字节结果。
说明为什么“encode 后 decode 又得 3”不能代替该独立预期。

**提交物：** 两步位图、两种长度的十六进制结果、回环测试的盲点。

**验收/评分点：** 位序与最小字节序列 2 分；完整八字节结果 2 分；回环证据局限 1 分。

### 11-03 选择正确的信号等待方式（5分）

**输入/约束：** 四种场景：同步取消通知、异步首帧、UI 防抖后的 pending、取消后一个超时窗口内不得出现 timeout。
所有 spy 在触发动作前安装，自定义参数需要注册元类型。

**任务：** 为四种场景分别选择计数断言、`QSignalSpy::wait()`、`QTRY_VERIFY` 或 `QTest::qWait` 等合适方式。
说明普通 `sleep_for` 与会处理 Qt 事件的等待差异，以及为何同步信号已经出现后再 wait 可能失败。

**提交物：** 四行“事件性质→等待/断言→失败含义”表，不要求每个 API 恰好用一次。

**验收/评分点：** 四种选择各 1 分；事件循环、spy 安装时机和元类型约束合计 1 分。

### 11-04 静态追踪 ACK、五字段与旧请求 ID（15分）

**输入/约束：** 不打开 CAN，使用学习测试夹具直接注入；非零发送返回值不证明真实发帧成功。
五字段顺序为 temperature、fanSpeed、blowMode、acOn、autoMode；X=(24,3,1,true,false)，Y=(26,4,2,false,true)。
以 41、42 表示先后两个非零本地 ID；只作纸面标签，不要求测试修改内部序号。
每个“变体”独立起步于 Y pending，避免上一条正确 ACK 清掉 pending。

| 步骤 | 动作 |
| --- | --- |
| A | 发 X 得到 ID 41；pending 期间再发 Y。 |
| B | 分别取消 ID 0、错误 ID 99，再取消 41，随后重复取消 41。 |
| C | 发 Y 得到 ID 42，注入 target=X、ack=1 的迟到帧。 |
| D | 向 UI 注入旧 ID 41 和零 ID 的完成/超时/取消通知。 |
| E | 依次独立试验五种 ACK：只将 Y 的一个字段改为 X 对应值。 |
| F | 注入完整匹配 Y、ack=1 的帧，然后再注入重复 ACK。 |

另开分支：取消 X 后再次发送 X，此时旧 X 的 ack=1 到达；说明当前协议能否识别它来自旧请求。
补答：无 pending 时，迟到 ack=1 与 ack=0 面板状态更新分别如何处理？

**提交物：** A—F 的返回值、pending、通知 ID、UI 是否可解锁表，以及同目标旧 ACK 的协议边界。

**验收/评分点：** 五字段匹配及重复 ACK 行为 5 分；取消、旧 ID 和状态轨迹 5 分；同目标不可区分及非 pending 分支 5 分。

### 11-05 实践：让字节与截断断言真正抓错（20分）

**输入/约束：** 只在学习副本新增独立 Qt 测试，参考 [现有解析测试](../../tests/tst_canframeparser.cpp)。
定义帧 1536、长度 8、信号 `signal : 0|2@0+ (1,0)`；可加一个先解码的 `earlier : 1|1@1+ (1,0)` 检查中途失败。
`out` 预置 `{signal:-1, keep:42}`；先输入独立写死的 `01`，再输入独立写死的 `01 80`。

**任务：** 对短帧断言 decode 返回 false 且整个 out 与原值相等；对成功帧断言 signal=3 且 keep 不残留。
对整帧 encode 断言完整八字节等于手算预期，不能只比较前两字节或只做回环。
只把学习测试中的预期暂改为 `0300000000000000`，保存一次应失败证据，再恢复正确预期保存应通过证据。
另加 Intel `7|2`、值 3 的独立字节用例，证明测试不是针对一条常量写死逻辑。

**提交物：** 数据行与关键断言、错预期/正确预期结果、构建环境；不能运行则交两份预计断言差异并明确标注。

**验收/评分点：** 独立 Motorola/Intel 字节及八字节比较 6 分；失败 out 完全不变和成功无旧键 6 分；故意错误能被检测 4 分；可复现入口与证据标识 4 分。

### 11-06 实践：旧轮次图像不能在停止后复活（20分）

**输入/约束：** 在学习副本参考 [相机测试](../../tests/tst_cameraservice.cpp)，只用 videotestsrc，不用 `/dev/video*`。
测试源取 64×48；人工排入可识别的 2×2 旧样本，必须在处理其 Qt 排队回调之前 stop。

**任务：** 编写 stop 与 stop/start 两个数据分支，监视整个 frameReady 序列是否曾交付 2×2 图，而非只看最终一帧。
先证明首帧非空且 64×48；stop 后即刻和再次处理事件后均应为空，重启则允许新轮次正常帧但禁止旧图。
解释捕获 generation、stop 增加 generation、回调同时检查 running 与 generation 的作用。
再为 EOS、ERROR、卡流写三行测试表：触发方法、等待条件、清空图像及错误信号次数。

**提交物：** 两分支断言关键片段、事件时序和结果；插件缺失则记录首条错误及未运行原因，不删断言。

**验收/评分点：** 首帧与尺寸 4 分；两个分支全序列旧图检查 6 分；代际检查解释 4 分；三类故障及事件循环 4 分；测试源/硬件边界和证据 2 分。

### 11-07 排障：三种“绿了”都可能没有证据（15分）

**输入/约束：** 以下故障样本仅供阅读，不要执行；不得靠加长所有等待或关闭全部检测规避问题。

| 样本 | 失败写法或结论 |
| --- | --- |
| A | spy 已提前安装；同步取消后 count=1，但紧接着 wait 返回 false，于是判取消失败。 |
| B | 取消后在 GUI 线程 sleep 超过 ACK 超时，timeoutSpy=0，于是声称计时器必已停止。 |
| C | 一次 ASan/UBSan 没报错，于是声称无泄漏、无数据竞争且板端 CAN/GL 都已验证。 |

**任务：** 每例给最小复现范围、需改的断言/观察方式和不能推出的结论。
C 还须给独立插桩构建方案：编译和链接均覆盖 address/undefined，保留栈信息，记录选择的测试与第三方库是否插桩。

**提交物：** 三张排障卡；不要求实际执行 Sanitizer，无运行库时可交构建参数及预期报告字段。

**验收/评分点：** 每例 5 分：根因或推理错误 2 分、具体纠正 2 分、证据边界 1 分。

### 11-08 综合验收：六套测试之外还缺什么（15分）

<details><summary>参考答案与评分提示（先独立完成）</summary>

**11-01**
- 六套为 `tst_core_cxx`（纯 C++ 边界/日志）、`tst_canframeparser`（Qt/DBC/字节）、`tst_cameraservice`（相机生命周期）。
- 另三套是 `tst_climateservice`（ACK/取消/防抖）、`tst_screenmanager`（切页/抢占）、`tst_ui`（服务到界面及绘制冒烟）。
- 后三套由 CTest 配置 offscreen；直接运行 GUI 二进制要自行设置。纯 C++ 可执行文件没有 Qt 单函数解析。
- suite 内有多个函数/数据行；`-N` 只列出注册项。核心不链接 Qt，但顶层配置仍查 Qt/GStreamer。

**11-02**
- Motorola 起始位 0 是 byte0 bit0，下一位跨到 byte1 bit7；值 3 的两个位均为 1。
- 最小序列 `01 80`，整帧为 `01 80 00 00 00 00 00 00`，即 `0180000000000000`。
- 固定字节应来自独立位图；用同一错误编解码器回环可相互抵消，得不到独立协议证据。

**11-03**
- 同步通知直接检查 spy.count()/参数；wait 等待下一次信号，不会把之前的那次当作新信号。
- 异步首帧可用 QTRY 检查非空/计数，或确认尚未到达后 wait 并检查结果；QTRY 对先到达更稳健。
- 防抖用 QTRY 等 pending；取消后的“没有 timeout”用 qWait 覆盖超时窗口后比较次数不增加。
- qWait、wait、QTRY 会让 Qt 事件有机会被处理；普通 sleep 阻塞该线程事件循环，可能制造假阴性。

**11-04**
- A：第二次发送返回 0，不替换 X；B：0/99 返回 false，41 首次 true、重复 false，取消通知带 41。
- C：X 与 Y 不同，旧 ACK 忽略，Y 仍 pending；D：旧 ID/零 ID 通知不解锁 UI 的新请求。
- E：五字段任一个不匹配均忽略；ACK 位为 1 不够，截断/缺字段也不得确认。
- F：完整 Y 确认 ID 42，清 pending、停计时器、更新确认状态；重复 ACK 因无 pending 被忽略。
- 本地 ID 不在 CAN 帧里；同目标旧 ACK 会满足当前匹配，无法可靠区分，需协议事务号等关联机制。
- 无 pending 时 ack=1 忽略；ack=0 且面板状态变化可同步状态；非零发送返回值不证明真实 CAN 发出。

**11-05**
- 关键断言是 `!decode(...)`、`out == previous`，成功后 signal=3 且无 keep；不要只查一个键的值。
- Motorola 整帧应为 `0180000000000000`；Intel `7|2` 值 3 应为 `8001000000000000`。
- 改成 `0300000000000000` 应在实际/预期字节比较处失败；恢复后仍保留字节断言。
- 加 earlier 信号能让“前一字段成功、后一字段失败”出现，检查整帧失败不泄露部分更新。
- 完整测试在学习副本完成；双端均调用同一算法生成期望或只比较前缀，不能得独立字节全部分。

**11-06**
- 首帧需非空且 64×48，start 成功不够；监视每次 frameReady，曾出现 2×2 即失败。
- stop 令 running=false 且轮次增加，旧回调被拒；重启后 running=true，仍靠 generation 不同拒绝旧图。
- stop 分支处理队列后仍为空；重启分支必须能收到新帧，不能用“从此不交付任何帧”假通过。
- EOS/ERROR 后等待 running=false、一次 cameraError、图像清空；卡流可暂停测试 pipeline，等待 2500 ms 后服务检查。
- 白盒注入不是生产接口建议；测试源需要插件，手工 start 重试不等于自动重连，未证明真实 GL/相机设备。

**11-07**
- A：检查同步 spy 的次数和 ID 即可，wait=false 仅说明等待期间没有新信号。
- B：改用 `QTest::qWait(kClimateAckTimeoutMs + 余量)` 后断言计数；普通 sleep 阻塞的定时器尚无机会暴露错误。
- C：独立 build-san；编译用 `-fsanitize=address,undefined -fno-omit-frame-pointer`，链接也加对应 sanitizer 标志。
- 保留第一份报告及分配/释放栈；第三方抑制须精确且有调查依据，关闭泄漏检测的一轮不能证明无泄漏。
- ASan/UBSan 只检测本次覆盖路径的相应问题，不证明数据竞争/线程安全，也不证明 CAN、KMS、触摸或硬件可用。

**11-08**
- 至少将字节/截断、五字段/旧 ID、代际帧各关联到可复现用例；同目标旧 ACK 列协议限制而非“已修复”。
- 当前 ScreenManager 简单返回测试不足以证明多个普通页最后访问历史；UI 亮像素不足以证明业务状态正确。
- 媒体 pollBus 无消息提前返回可能影响进度，ERROR 后 healthy 恢复路径不明确；健康无专项 suite，需另建覆盖。
- 插件缺失、CTest 零用例、offscreen GL 限制分别记录，不当作逻辑通过；真实屏幕/音频/触摸留待授权实机验收。
- 定向结果、插桩范围和未测项须分开；完整纸面方案可验收知识，但不能填写实际测试通过。
