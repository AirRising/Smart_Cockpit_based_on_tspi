# 从零写一个 Qt 智能座舱

这套教程面向刚接触 C++、Qt 和嵌入式 Linux 的读者。目标不是“把代码复制到板子上”，而是理解每条数据如何变成界面、每个操作如何获得确认，以及设备出错时程序应该怎样表现。

**先在 Linux 电脑上做出可运行的小程序，再逐步写成项目，最后上板。没有泰山派、CAN 适配器和摄像头，也能完成大部分学习。**

配套 [练习题库](exercises/README.md)：14 套逐章练习 + 1 套开发指南综合题，每套 8 题、100 分，含动手任务、验收标准和折叠参考答案。建议每读完一章就完成对应题集，再继续下一章。

这是教学与研究项目，不是经过车辆功能安全认证的量产系统。不要把示例控制帧发到在用车辆上。

## 1. 先选一条路线

### 完全零基础

按 01 → 02 → 03 学环境、C++/Qt 和工程拆分；接着按 04 → 12 分模块学习。每章完成练习后，再按 13 的里程碑把模块组装到**自己的空目录**。最后用 14 检查是否真正掌握。

不要求一次记住所有语法。遇到新词，先看本章解释，再做一个最小实验。

### 会 C++，但没做过车载界面

读 01 确认环境，重点做 04、05、07、09、11，再按 13 实现项目。06 解释本项目的绘制与缓存；12 解释宿主机和板端的区别。

### 已经能运行，想查源码

从 [开发指南：源码参考](DEVELOPMENT.md) 查类与数据流，从 [已知边界与练习](14-known-issues-and-exercises.md) 查哪些能力尚未完成。不要只看界面上有没有按钮来判断功能是否实现。

## 3. 教程使用约定

### 三个目录，不能混淆

```bash
PROJECT=/home/air/qt/Smart_Cockpit_based_on_tspi
HOST_BUILD="$HOME/build/smart-cockpit-host"
WORK="$HOME/smart-cockpit-lab"
```

- `PROJECT`：这份参考仓库；你的路径不同就改第一行。
- `HOST_BUILD`：编译参考项目的产物目录，不存手写源文件。
- `WORK`：自己的学习目录。02、03、06 的独立实验放在不同子目录；13 的完整重建放在 `WORK/cockpit`。
- shell 变量只在当前终端生效。打开新终端要重新设置。
- 如果目录已经存在，先查看内容；不要用教程里的文件覆盖自己的已有作业。
- 文档内链接使用相对路径，源码链接可直接跳到参考实现。

### 代码块分为三类

1. **完整文件**：给出文件名和全部内容，可以在指定练习目录创建后编译。
2. **源码摘录**：来自现有工程，依赖周围类、成员和头文件，不能单独编译。
3. **流程/伪代码**：用于讲逻辑，不冒充完整实现。

终端命令也要看适用环境：桌面开发机、隔离虚拟 CAN、目标板不是同一台机器。带 `sudo` 的命令会修改系统，应理解并获得权限后再执行；阅读教程不需要执行部署或更改真实设备。

## 4. 当前代码的定位

主线是 **C++17 + Qt 5.15 Widgets + CMake ≥ 3.21 + GStreamer + Linux SocketCAN**；推荐 Ubuntu 22.04 或更新版本、Debian 12 的桌面开发环境。没有 QML、Qt Designer `.ui` 或前端网页。Qt6 是构建选项，不代表所有宿主环境与板端都已验证兼容。

原项目声明的最低版本较低，但当前源码使用了 Qt 5.14 才提供的 `Qt::hex/dec`，教程命令中的 `ctest --test-dir` 也需要 CMake ≥ 3.20；不要把配置文件能通过版本检查当成完整兼容性证明。独立窗口示例的较低最低版本声明不改变本系列的统一学习环境。

源码按三层构建：

```text
smart_cockpit_cxx   纯 C++：协议解析、日志线程
        ↓
smart_cockpit_core  Qt 适配、车辆/外设服务、界面
        ↓
smart-cockpit      main.cpp：创建、连接、启动、退出
```

当前回归覆盖包括 CAN 跨字节边界与 Motorola 位序、空调取消及完整目标回执校验、摄像头断流与旧帧隔离。**仍有未修复问题**，包括扩展 CAN ID、普通页面返回顺序、部分空调按钮和媒体播放行为，详见 14。

尤其注意：

- `--sim` 不连接 CAN，也不会自动产生空调 ACK；空调等不到确认时回滚是预期路径。
- 空调本地 requestId 没有写进 CAN 报文；同目标的旧 ACK 仍可能无法区分。
- 摄像头失败后会清空画面，可以再次调用 `start()`；尚无自动重连策略。
- 普通电脑上的测试和显示验证不等于板端、真实摄像头、音频或整车验证。

## 5. 怎样判断自己“学会了”

不要用阅读页数衡量，试着回答并实际演示：

- 为什么 CAN 的两个字节可以表示速度，却不能直接拿来显示？
- 为什么不能在 GStreamer 回调中直接操作 QWidget？
- 为什么“请求已受理”“总线写成功”“车辆已确认”是三件事？
- 为什么 encode→decode 互相通过，仍可能是两个函数一起写错？
- 为什么窗口仍显示上一帧，不代表摄像头仍在工作？
- 为什么编译为 ARM，并不代表所用 Qt/GStreamer 库也来自 ARM？

能从空目录实现这些链路，并用失败用例证明它们的边界，才算完成本教程。
